# CV Studio

CV Studio is a multi-user, LaTeX-backed résumé workspace that combines visual
editing, deterministic PDF generation, annotations, job-description analysis,
and conversational assistance.

The product is intended to feel like a focused combination of Overleaf and a
modern document editor: users can work visually, inspect or edit the underlying
TeX, and always download the PDF generated by `pdflatex`.

## Product direction

The planned workspace contains four areas:

1. **Library** — CVs, folders, job descriptions, revisions, and exports.
2. **Visual editor** — direct structured editing with page-like styling.
3. **TeX/PDF workspace** — source mode and an authoritative compiled preview.
4. **Assistant** — document-aware chat and annotation-driven change proposals.

Users will be able to select content in the visual editor or compiled preview,
add an annotation, and request a change. Proposed changes are shown as diffs and
only modify the document after explicit approval.

## Chosen architecture

| Area | Technology |
| --- | --- |
| Web application | React, TypeScript, Vite |
| Visual editor | Tiptap/ProseMirror with a constrained résumé schema |
| TeX source editor | CodeMirror 6 or Monaco |
| PDF preview | PDF.js |
| API | Python, FastAPI |
| Persistence | PostgreSQL |
| Background work | Redis-backed compilation worker |
| PDF generation | Sandboxed `pdflatex` |
| File storage | Local object storage in development; S3-compatible storage in production |
| AI providers | Provider adapter; Ollama first, hosted providers optional |

Vite is the frontend build tool; React is the UI framework.

## Document model

LaTeX remains the canonical export representation, but arbitrary TeX is not a
safe WYSIWYG editing format. CV Studio therefore stores a structured résumé
document alongside its generated TeX:

```text
Structured résumé document
        │
        ├── visual editing and annotations
        ├── revision history and AI diffs
        └── deterministic TeX serialization
                         │
                         └── pdflatex → PDF
```

Each document block receives a stable ID. Annotations attach to those IDs and
text offsets rather than fragile PDF coordinates. PDF selections can additionally
store page geometry and SyncTeX information for navigation.

## Core workflows

### Edit and compile

1. Edit a résumé block visually or edit its TeX source.
2. Autosave the document as a new revision.
3. Queue a debounced compilation job.
4. Run `pdflatex` in an isolated temporary directory.
5. Store the PDF and compiler diagnostics.
6. Refresh the PDF viewer without reloading the workspace.

### Annotate and request a change

1. Select text and choose **Annotate** or **Ask AI**.
2. Save the selection against a stable document block.
3. Enter the requested change.
4. Generate a proposed structured-document and TeX diff.
5. Accept or reject the proposal.
6. Recompile after an accepted change.

### Tailor to a job description

The first release will accept pasted text and uploaded text/PDF documents. URL
ingestion will follow later because it requires fetching, extraction, redirects,
site-specific handling, and appropriate security controls.

## Repository status

This repository currently contains the original dependency-free interaction
prototype:

- `index.html` — three-pane interface
- `styles.css` — responsive application styles
- `app.js` — prototype interactions
- `server.py` — local document indexing and draft API

The prototype validates the layout and workflow but is not the production
architecture. It currently reads résumé sources from the parent CV workspace.
The migration described in [PLAN.md](PLAN.md) will replace it with the React and
FastAPI applications.

## Run the current prototype

Requirements:

- Python 3.11+
- A parent CV workspace containing `source/` and `applications/`

```bash
python3 server.py
```

Open <http://localhost:8000>.

## PDF compilation requirements

The production service requires a TeX installation with `pdflatex` and the
packages used by the approved résumé templates. Compilation will run with:

- shell escape disabled;
- CPU, memory, file-size, and time limits;
- an approved package/template policy;
- isolated temporary directories;
- persisted logs and actionable line-level diagnostics.

## Multi-user and security requirements

- Every CV, revision, annotation, job description, and artifact is owned by a user.
- Authorization is enforced in API queries, not only in the frontend.
- TeX compilation never runs inside the API process.
- Uploaded files are size- and type-validated.
- Secrets remain server-side and are never stored in browser state.
- AI suggestions cannot silently modify a document.
- Source and compiled artifacts support retention and deletion policies.

## GitHub publishing

After creating an empty GitHub repository, connect and publish this local
repository:

```bash
git remote add origin git@github.com:<your-username>/cv-studio.git
git push -u origin main
```

Do not commit API keys, database credentials, uploaded résumés, or generated
artifacts. The repository does not currently declare an open-source license;
choose one before accepting external contributions.
